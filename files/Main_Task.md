Дай полезный ответ и задай следующий вопрос.

История диалога:
- Нужно передавать в LLM последние сообщения диалога.
- Не нужно сохранять историю между перезагрузками страницы.
- История может храниться в памяти браузера или на backend во время текущей сессии.

Форма заявки:
- Поля: имя, e-mail, телефон.
- При отправке заявки сохранить данные в простой файл leads.json или leads.csv.
- После отправки показать пользователю сообщение об успешной отправке.
- Валидация минимальная:
  - имя не пустое;
  - e-mail содержит @;
  - телефон не пустой.

Техническая реализация:
Можно сделать на FastAPI или Flask.
Фронтенд можно сделать на обычном HTML/CSS/JavaScript.
Главное — чтобы всё запускалось в Replit Preview.

Желательная структура файлов:
- main.py
- requirements.txt
- rag_knowledge_base_20260519_185732.txt
- leads.json или leads.csv
- static/style.css
- templates/index.html

API:
1. GET /
   Возвращает главную страницу.

2. POST /chat
   Вход:
   {
     "message": "...",
     "history": [...]
   }

   Выход:
   {
     "chunks": [
       {
         "rank": 1,
         "similarity": 0.83,
         "text": "..."
       }
     ],
     "answer": "...",
     "llm_model_used": "...",
     "llm_error": null
   }

3. POST /lead
   Вход:
   {
     "name": "...",
     "email": "...",
     "phone": "..."
   }

   Выход:
   {
     "success": true,
     "message": "Спасибо! Заявка сохранена. Менеджер свяжется с вами."
   }

requirements.txt:
Добавь все нужные библиотеки, например:
fastapi
uvicorn
jinja2
python-multipart
sentence-transformers
scikit-learn
numpy
requests

Если используешь Flask — добавь Flask вместо FastAPI.

Обработка ошибок:
- Если файл базы знаний не найден, показать понятную ошибку.
- Если txt-файл не читается, показать понятную ошибку.
- Если не удалось загрузить embedding-модель, показать понятную ошибку.
- Если LLM не ответила, всё равно показать найденные чанки.
- Ошибки не должны ломать интерфейс.

Критерии готовности:
1. Приложение открывается в Replit Preview.
2. В чате сразу есть приветственное сообщение.
3. Пользователь задаёт вопрос.
4. Система показывает 5 найденных чанков.
5. После чанков появляется ответ AI-продажника.
6. AI-продажник задаёт следующий вопрос.
7. Если OpenRouter/LLM не сработал, чанки всё равно показаны.
8. Форма заявки справа сохраняет имя, e-mail и телефон.
9. Интерфейс светлый, русский, бело-зелёно-серый.
10. База знаний читается из файла rag_knowledge_base_20260519_185732.txt.
